# ADR を書く

`docs/adr/README.md` の規約（連番、欠番も再利用もしない、目次の表に 1 行）を人が数えると必ずずれるので、
定型部分はスクリプトに任せて本文だけ書く。

## 手順

### 1. 書くかどうかを決める

書くのは「あとで前提を確認したくなる判断」だけ。次のどれかに当てはまるとき。

- 選択肢が複数あって、落とした案がある（ADR 0001, 0005, 0013）
- 制約が非自明で、知らないと踏む（ADR 0003 の「config を変えたら apply」）
- 外部の事情に依存していて、状況が変わったら見直す（ADR 0010 の「Codex はメトリクスを送らない」）

バグ修正、表現の調整、バージョンを上げただけの変更には要らない。

### 2. 枠を作る

```bash
bash .claude/skills/new-adr/scripts/new-adr.sh <english-kebab-case-slug> "<日本語の題名>"
```

題名は決めたことを一文で言い切る。「〜の検討」「〜について」にしない。

```bash
# 良い例
bash .claude/skills/new-adr/scripts/new-adr.sh pin-image-versions "イメージはパッチバージョンまで固定する"
```

スクリプトがやること。作られたファイルのパスが出力される。

| 対象 | 内容 |
| --- | --- |
| `docs/adr/NNNN-<slug>.md` | `template.md` を展開し、H1 と日付を埋める |
| `docs/adr/README.md` | 表の最終行のあとに `\| [NNNN](...) \| 題名 \| 採用 \|` を足す |
| `CLAUDE.md` | 「番号は連番で欠番も再利用もしない（次は NNNN）」を進める |

### 3. 本文を埋める

見出しは変えない。既存の ADR（[0013](../../../docs/adr/0013-native-configs-for-prek-and-ryl.md) が直近）に合わせる。

- **状況** — 何に困っていて何を決める必要があったか。そのとき分かっていた事実と制約だけ。
  「あとで読む人がなぜこれを考える羽目になったか追える」ところまで書き、それ以上は書かない
- **判断** — 決めたこと。**落とした案があるなら落とした理由も残す**。バージョンや設定値のように
  あとで照合するものは表にする
- **結果** — これから何が変わるか。運用で踏む手順、残った制約、この判断を見直すきっかけになる条件

既存の ADR を置き換えるなら、古い方の状態を「置き換え済み」に変え、新しい方から古い番号へリンクを張る。

### 4. 検査する

```bash
prek run --all-files rumdl
```

## 書きぶり

日本語。AI 臭い表現（「実現」「活用」「包括的」、意味のない三点列挙、両論併記）を避ける。
決めたことを書く場所なので、両論を並べて終わらない。落とした案は「落とした」と書く。
